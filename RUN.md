# Запуск и эксплуатация Canopy

## Локальный запуск

Выполняйте команды из корня репозитория. Нужен Node.js 22 или новее:

```bash
npm ci
node runtime/run.mjs apps/checkout/app.json --check
node runtime/run.mjs apps/checkout/app.json --port 8901
```

Откройте [каталог товаров](http://127.0.0.1:8901/Product).
Демо-администратор: `admin@checkout.test` / `admin123`. Stripe, Postmark и Slack
в примере работают в локальном sandbox Canopy. Чтобы установить только
зависимости для запуска, используйте `npm ci --omit=dev`.

## Отдельный каталог состояния

Без флагов рантайм пишет состояние рядом с `app.json`. Для отдельного каталога:

```bash
state="$(mktemp -d)"
node runtime/run.mjs apps/checkout/app.json --port 8901 \
  --db "$state/data.sqlite" --trace "$state/trace.jsonl"
```

В каталоге базы будут SQLite, загруженные файлы (`files/`), ключ сессий
(`session.key`), хранилище секретов (`secrets.enc`, `secrets.key`, если
используется ключ из файла) и настройки режимов коннекторов (`deploy.json`).
Часть файлов появляется только при использовании соответствующей возможности.
`--trace` задаётся отдельно: без этого флага журнал остаётся рядом с графом.
Пути к плагинам и фронтенду по-прежнему считаются от каталога графа.

Для постоянной установки используйте постоянный каталог вместо `mktemp`.
Не коммитьте состояние. Для резервной копии остановите приложение и сохраните
состояние вместе с версией графа и плагинов. Копии и ключи храните с ограниченным доступом.

## Операционные команды

Передавайте один и тот же `--db` при запуске сервера и при работе с его состоянием
через CLI. Например, для каталога из предыдущего шага:

```bash
node runtime/run.mjs apps/checkout/app.json --db "$state/data.sqlite" --connectors status
node runtime/run.mjs apps/checkout/app.json --openapi --out "$state/openapi.json"
```

Как задать секрет через stdin, включить live и вернуться в sandbox, описано
в [руководстве по коннекторам](docs/CONNECTORS.md#use-a-connector).
Локальный sandbox не обращается к провайдеру; тестовый API провайдера требует
сетевого доступа и тестовых ключей. Проверяйте режим перед первым внешним вызовом.

## Публичное развёртывание

- Рантайм слушает `127.0.0.1`. Используйте HTTPS на входном прокси, сохраняйте
  публичный `Host` для проверки `Origin` и включите `AG_SECURE_COOKIES=1`
  за HTTPS. Не используйте произвольные клиентские proxy-заголовки для определения схемы.
- Уберите демонстрационные учётные записи и пароли. Ограничьте частоту обращений к
  `/login` и `/register`, включая варианты под `/api` и `/admin`.
- Ограничьте доступ к каталогу состояния. Проверьте права `0600` у существующих
  `session.key` и `secrets.key`. При использовании `CANOPY_MASTER_KEY` передавайте
  его через окружение: 32 байта в Base64. Он имеет приоритет над `secrets.key`.
- Указывайте конечный URL: коннекторы не следуют HTTP-редиректам. Ограничьте
  исходящую сеть рантайма и мостов, используйте минимальные права учётных записей.
  Плагины выполняются как доверенный код внутри процесса.
- Согласуйте лимиты запросов на прокси с рантаймом. Для обычных форм, JSON и
  webhook лимит тела составляет 1 МиБ. `AG_MAX_UPLOAD` задаёт лимит одного
  файла в байтах (8 МиБ по умолчанию). Общий лимит multipart: четыре таких
  лимита плюс 1 МиБ.

## Сгенерированный фронтенд

В графе CRM указан `"web": "web/dist"`: сгенерированный интерфейс живёт на `/`,
встроенные экраны на `/admin`. Можно запустить уже собранный пример:

```bash
node runtime/run.mjs apps/crm/app.json --port 8902
```

Для локального просмотра: [CRM](http://127.0.0.1:8902/),
администратор `admin@crm.test` / `admin123`. Чтобы пересобрать фронтенд,
следуйте [инструкции webgen](webgen/README.md#generate-and-build) из корня
репозитория. Правьте граф или генератор, а не сгенерированные файлы вручную.

## Локальные проверки

Запускайте проверки последовательно. На Linux, где доступны пользовательские
systemd scopes, пример ограничения до одного CPU по времени и 1 ГиБ памяти,
с низким приоритетом диска:

```bash
systemd-run --user --scope --quiet -p CPUQuota=100% -p MemoryMax=1G \
  ionice -c3 nice -n 10 node --test --test-concurrency=1 'tests/*.test.mjs'
```

Для приёмочных проверок выбранных приложений запустите `node verify/run.mjs shop crm`
под теми же ограничениями. Приёмка использует порт 8999 для локального HTTP-приёмника
и порты начиная с 8910 для приложений. Некоторые графы отправляют запросы именно
на 8999, поэтому освобождайте этот порт перед полным прогоном.
Подробности: [тесты](TESTS.md) и [ограничения проекта](AGENTS.md#commands).
