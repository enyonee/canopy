## Кривая каталога

Главная цифра проекта — сколько нового требует N-е приложение. Честная оговорка о методе:
я прочитал все десять задач и расширил рантайм **одним заходом**, а не по одному приложению
за раз. Поэтому ниже — не хронология открытий, а **атрибуция**: какое приложение первым
потребовало бы каждой возможности. Настоящая кривая требует сборки по порядку и без
предварительного чтения.

| приложение | что понадобилось впервые |
|---|---|
| todo | база: `data`, `override.list/form`, `actions`, блок `db.toggle` |
| forum | `identity`, `seed`, связанные списки в карточке, `fill`, сохранённые списки `lists` |
| campus | `events`, блок `db.createRow`, подтверждение действия |
| sms | `dashboards` (карточки и группировки), фильтры по enum, подписи булевых полей |
| survey | серверная валидация с ошибками полей, статические `pages` |
| drivers | — ничего нового |
| internships | — ничего нового |
| studygroups | — ничего нового |
| finance | — ничего нового (несколько метрик в одной таблице) |
| wheel | блок `random.pick`, действие без сущности, кнопка действия на странице |
| trivia | блок `check.matchRef` |

**Четыре из последних семи приложений не потребовали ничего нового.** Оба разрыва в конце —
`wheel` и `trivia` — это задачи, выбранные *за краем* заявленного класса: случайность и
проверка ответа. Внутри класса «данные, формы, воркфлоу» каталог насытился после четвёртого
приложения.

## Учёт промахов по трём счётчикам

Как требует план: каждый промах закрыт одним из трёх способов, и они считаются раздельно.

- **Новые виды узлов — 6** (`seed`, `identity`, `pages`, `dashboards`, `lists`, `events`).
  Плюс опции внутри `override`: `related`, `fill`, `labels`, `sort`, `confirm`/`after`.
  Это рост формата, и он не бесплатный: шесть новых видов на десять приложений — много.
- **Новые коннекторы — 0.** Ни одно из одиннадцати приложений не ходило наружу.
- **Составных блоков — 0** (композиции в языке пока нет).
- **Новых примитивных блоков — 3** (`db.createRow`, `random.pick`, `check.matchRef`).

Два блока, добавленных «на будущее» (`db.createIn`, `db.setOnRelated`), удалены: их не
использовало ни одно приложение. Каталог выводится из приложений, а не угадывается.

## Дефекты рантайма, найденные приложениями

Все четыре — на одной границе: **объявленное умолчание против присланного значения**.

1. Приведение булева поля не понимало числовую единицу — `db.toggle` тихо писал ноль.
2. `ALTER TABLE ADD COLUMN` не досевал объявленное умолчание: старые строки оставались с NULL.
3. Снятая галочка на создании молча превращалась в объявленное умолчание `true` — неактивная
   вакансия попадала в список активных.
4. Переписывание рантайма ради общности сломало два зелёных теста `todo` (подписи булевых
   полей и меню). Поймано повторным прогоном — ровно то, для чего в плане золотые трассы.

Отдельно — три дефекта **самого стенда проверок** (регулярка для id, экранированный апостроф,
мусорный `fetch`). Их стоит считать отдельно: они не говорят о языке ничего, но показывают,
что проверки нужно проверять.

## Где мои проверки слабее оригинальных тестов

Это важнее приятных цифр:

- **studygroups, тест 2**: оригинал требует, чтобы ресурс **скачался файлом на устройство**.
  В графе есть только ссылка, файлов рантайм не умеет вовсе. Моя проверка принимает ссылку —
  то есть проверяет более слабое утверждение. Это **непокрытый промах**: нужен коннектор файлов.
- **internships, тест 2**: оригинал требует **письмо-подтверждение** заявки. Письма никто не
  шлёт; моя проверка принимает подтверждение на экране. Нужен коннектор почты.
- **campus, тест 6**: оригинал говорит о «получении уведомления», у нас уведомление появляется
  строкой в списке, а не доставляется.

То есть из 68 проверок **три проверяют ослабленное требование**, и все три упираются в один
и тот же пробел — наружу приложение не ходит.

## Чего этот прогон по-прежнему не доказывает

- Браузерный агент бенчмарка не запускался: тесты переведены в HTTP-сценарии мной.
- Приложения и проверки писал один автор — дисциплина «тесты скрыты» не соблюдена.
- Бейзлайнов нет: не с чем сравнить ни токены, ни регрессии.
- Задачи «за краем класса» выбраны мной, а не жребием.

Прогон показал, что **конструкция держит одиннадцать разных приложений при семи блоках** —
и по-прежнему ничего не сказал о том, что она выигрывает у обычного кода.
