# Вертикальный срез: задача 000080 из WebGen-Bench

Шаг 1 плана — одна настоящая задача, пройденная целиком, чтобы вскрыть дыры конструкции
до того, как построено лишнее.

## Что взято

Задача `000080` из `data/test.jsonl` официального [WebGen-Bench](https://github.com/mnluzimu/WebGen-Bench)
(101 задача, 647 тестов). Формулировка чужая, тесты чужие — восемь случаев `ui_instruct`:
создание, редактирование, отметка выполненного, удаление, поиск, фильтр, навигация и
внешний вид (`lavender` фон, `indigo` компоненты). Копия задачи — `tasks/000080.json`.

## Что получилось

**Приложение целиком — 84 строки графа, ~420 токенов** (`apps/todo/app.json`): одна сущность
из четырёх полей, один `override` списка, одно действие из одного блока. Ни одного чистого
листа не понадобилось — закрытая форма без вычислений задачу покрыла.

**Каталог — четыре блока**: `db.create`, `db.update`, `db.delete`, `db.toggle`. Промахов
каталога ноль.

**Рантайм — 625 строк, ноль зависимостей** (Node 22, встроенный `node:sqlite`):
разбор типов, чекер, хранилище с миграциями из диффа, каталог, скаффолд-рендерер,
интерпретатор, применение патчей. Приложение — каталог из трёх файлов:
`app.json`, `data.sqlite`, `trace.jsonl`.

**Проверки — 8/8** (`verify/todo.mjs`), включая внешний вид. Снимок: `demo/todo-list.png`.

## Изменение требования патчем

`apps/todo/change-1-priority.patch.json` — добавить приоритет, показать колонкой, дать фильтр:

```
381 байт патча (~110 токенов) против ~420 токенов на перепечатку приложения
```

Разница вчетверо на приложении из 84 строк; на приложении из тысячи строк это уже другой
порядок. Миграция выведена из диффа автоматически, лог рантайма:
`add column task.priority (+ backfilled 4 row(s) with "normal")`. Данные пережили изменение,
регрессий нет — 8/8 после правки.

## Что срез вскрыл

Два дефекта рантайма, оба одного семейства — умолчания и приведение типов:

1. `coerce` для булева поля не понимал числовую единицу, и `db.toggle` тихо писал ноль.
   Отметка выполненного не работала, тест 3 падал, тест 6 падал следом.
2. `ALTER TABLE ADD COLUMN` не досевал объявленное умолчание: у старых строк оставался NULL.
   Объявленное умолчание — обещание про все строки, а не только про новые.

Оба — ровно тот класс, о котором план предупреждает: **баг рантайма выглядит как свойство
языка**. Отсюда гейт эталонов и дифференциальный интерпретатор перестают быть перестраховкой.

Ошибки чекера на нарочно сломанном графе:

```
✗ /data/Task/due: unknown type "date"; known: text, longtext, bool, int, time, enum[...], ref:Entity
✗ /override/Task.list/columns: field "priority" does not exist on Task
    → known fields: title, notes, done, createdAt
✗ /override/Task.list/rowActions/0: unknown action "togle"
    → built-in: edit, delete; declared in /actions: toggle
✗ /actions/0/do/0/block: unknown block "db.togle"
    → did you mean: db.toggle?
```

## Чего этот срез НЕ доказывает

- Тесты переведены мной в HTTP-сценарий; **браузерный агент бенчмарка не запускался**.
- Приложение и проверки писал один и тот же автор — дисциплина «тесты скрыты» не соблюдена.
- Бейзлайнов нет: не с чем сравнивать ни по токенам, ни по регрессиям.
- Одна задача, причём из самых простых в наборе. Про кривую каталога она не говорит ничего.

То есть срез показал, что конструкция **работает**, и не показал, что она **выигрывает**.
Второе — работа шагов 2–4 плана.
